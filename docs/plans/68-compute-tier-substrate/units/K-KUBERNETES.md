## 3. Design — where every value lives, who reads it, how it fails

**Config values.** Non-secret knobs live in one TOML per tier, shipped as a ConfigMap and mounted read-only at `/etc/jammi/jammi.toml` (third resolution step). Secrets (`JAMMI_AUDIT_MASTER_KEY`, `JAMMI_CATALOG__POSTGRES__URL`, `JAMMI_BROKER__JET_STREAM__URL`) live only in Secret `jammi-server-secrets`, injected via `envFrom` (`optional: false`), and the env layer wins over the file. The pod name enters as `JAMMI_WORKER_ID` via `env` (downward API), read once at session boot as the `instances.label`. Readers: `JammiConfig::load` in `serve` and `probe` (`main.rs:100-105,170-176`).

**Tiers.** Shape C base: every replica `services = "all"`, `[worker] enabled = true, kinds = "all"` — the replicas ARE the workers. Shape D: the base ConfigMap is replaced (`enabled = false`) and a cu12 Deployment claims with `enabled = true, kinds = "all"`, `services = []` (core still mounts). ci: base minus `[storage]`, replicas 1, kind-loaded image, hostPath fixtures.

**Failure modes and behaviour.**
- Stale image (pre-`[worker]`): `failed to load config` → CrashLoopBackOff. Remedy per D6. Post-merge acceptance A13 catches it before anyone deploys.
- Wrong ConfigMap key: the file is mounted under a name the chain never reads → silent defaults. Prevented by the `jammi.toml=<file>` key form and oracle K2-O4.
- Missing Secret: `optional: false` → pod stuck `CreateContainerConfigError`, never ready. Stated in README.
- Rolling update with a job in flight: SIGTERM → RPC drain → keeper joined → hold `lost` → trainer bails at the next epoch boundary (bundle already written at the previous boundary, and written at THIS boundary if reached before the flip) → row stays `running` until lease expiry → reclaim re-queues (`attempts + 1`, fails permanently at 3) → next claimant resumes from `{job_id}/_resume/`. Grace bounds only the drain; a SIGKILL during a slow drain skips `close` entirely. Stated in README (D12).
- Pod replacement loses `emptyDir` (HF cache + artifacts): re-download on the next start; durable state is catalog/broker/result root. Seam named (RWX PVC, init-container pre-pull, `[models] hub_cache_dir`/`offline`); Compose asymmetry stated (named volume persists, `docker-compose.yml:42-47`).
- Two `instances` rows sharing a label after an in-place restart until the next boot's `prune_instances` reaps the stale one — label is non-unique by design.
- Liveness: a dead keeper is not detected today (D7).
- kubeconform never inspects `ConfigMap.data`; the TOML files are proven by K5's fence test through `{{#include}}`.
