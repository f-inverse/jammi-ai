## 1. Decisions

**D1 (brief F1) — Deletion set = per-version Parquet sidecar with a VERSION horizon.** `{table}__v{N}.deletes.parquet`, columns `_row_id Utf8 NOT NULL, _dead_through_version Int64 NOT NULL`, sorted by `_row_id`, cumulative (version N's file is the whole mask). Entry `(K, h)` masks `K` in every fragment and segment whose stamped `version <= h` and nowhere else. Every fragment (in the manifest) and every segment (`index_segments.version`) is stamped with its producing version; base artifacts are stamped with the base version number (§3.1). A refresh producing N writes `entry[K] = max(entry[K], N-1)` for every superseded or deleted key, so artifacts stamped N are never self-masked and an updated key present in two segments is unambiguous. Why a version, not a segment id: segment ids are allocated by an insert race (`crates/jammi-db/src/store/mod.rs:1739-1756`) and a zero-row write allocates none (`store/mod.rs:2134-2137`), so the id space is not a stable horizon; the version number is allocated once before any artifact is written (D2). Why a sidecar, not catalog rows: object-store native, one artifact per version whose digest folds into identity (K7), reconcile already enumerates sidecars by URL (`store/reconcile.rs:998-1041`), same file on `file://` and object store (B4). Row identity across segments is `_row_id` (`index/sidecar.rs:325, :787-788`), so one mask serves the ANN merge, the SQL/exact scan and `read_vector_by_key`. Precedent: Iceberg equality deletes + sequence numbers (§9).

**D2 (brief F2) — One logical table, versions in a child table, monotonic allocation.** The `result_tables` row (PK `table_name`, `catalog/schema.rs:90-107`) stays the identity every predicate renders (`catalog/result_repo.rs:269-283`; FK from `index_segments`, `schema.rs:780`); "newest ready" stays `ORDER BY created_at` (`result_repo.rs:1399-1405`); a version-per-row scheme would shadow tables in `resolve_embedding_table` (`:1338`) and break `derives_from` anchors (`store/freshness.rs:441-449`). Versions live in `result_table_versions` (§3.10) with `result_tables.current_version` (Iceberg current-snapshot-id + atomic swap) and `result_tables.next_version INTEGER NOT NULL DEFAULT 0`, the monotonic allocator: a number is allocated exactly once, never reused; a failed or crashed version keeps its number; `expire_versions`/reap delete rows and stamped artifacts and never touch `next_version`. `current_version IS NULL` = never refreshed = today's table with zero behaviour change. Two refreshes on one parent both allocate; the second to publish misses `current_version = parent` and gets `ParentMoved` (D5; round 5, M9: `CasFailed` is the building-row lease class — a version-row CAS matching no row because it already left `building`; a parent-pinned CAS miss on `current_version` is `ParentMoved`, per `crates/jammi-db/src/error.rs`'s own doc on each variant).

**D3 — Base version published as manifest-write + CAS in ONE transaction, no building row.** On the first refresh of a table with `current_version IS NULL`, step 0 reads `next_version` (= B), writes `{table}__v{B}.version.json` describing today's table (fragments = `[parquet_path]` stamped B, segments = `index_segments WHERE version IS NULL` stamped B, deletes none, descriptor copied verbatim from `.materialization.json`, `parent = null`), then one transaction: `INSERT result_table_versions (…, status='ready', identity, live_rows=row_count, masked_rows=0)` + `UPDATE result_tables SET current_version = B, next_version = B+1 WHERE table_name = $t AND status='ready' AND current_version IS NULL AND next_version = B AND <tenant arm>` (1 row, else rollback). The base publish refuses (K2) when `dimensions IS NULL` on the row (`result_repo.rs:122`), so a versioned row without `dimensions` cannot be created by this unit. Crash before the transaction leaves an orphan `__v{B}.version.json` that the next attempt overwrites at the same path (same content modulo `produced_by`/`produced_at`); reconcile's object→row arm is age-gated (`apply=true` requires `grace >=` the lease duration, `store/reconcile.rs:89-98, :184-199`), stated as a dependency, and the publisher re-`exists()`s the manifest after the CAS and re-PUTs if absent (idempotent). Two concurrent base publishers write the same path and exactly one CAS applies; the loser re-reads `current_version = B` and proceeds with parent B. **identity(base) := the table's `.materialization.json` `artifact` hex exactly** (`store/manifest.rs:876-877`), byte-equal to today's `ResultDigest` anchor (`freshness.rs:448-449`; `store/mod.rs:920-931`), so publishing the base changes no downstream anchor and a `NoChange` refresh leaves every `derives_from` dependent `Fresh`. Versions >= B+1, including compaction, fold `parent_identity`; the base is the only chain root; only a recompute to a NEW table starts a new chain (D9).

**D4 (brief F3) — `_content_hash` is a NULLABLE fifth column of `embedding_table_schema`.** `Utf8` hex SHA-256 over the embedded columns in the descriptor's `columns` order (`manifest.rs:321-335`), domain tag `jammi.content_hash.v1`, per column `[tag u8][len u64 LE][bytes]` with tags `s` (string after cast), `b` (binary-family bytes; dead for text tasks because `validate_text_column` refuses binary, kept for the image path-string case), `n` (null). The hash is computed INSIDE the `jammi_content_hash` UDF over the RAW columns using the runner's own kernel (`validate_text_column` + `arrow::compute::cast`, `crates/jammi-ai/src/inference/mod.rs:92-124`; joined per row by `arrow_to_texts` `:48-67`), so base, refresh and inference share one rendering by construction; a SQL-side `CAST` with a coarser rendering would hash distinct values equal → `Unchanged` → a STALE vector served (a wrong answer). Model/task/device are folded by the table's `definition_hash`, never per row (`docs/guide/src/materialization-contract.md:81-84`). Only `EmbeddingPipeline` writes real hashes; `embedding_batch` (`store/mod.rs:2242`) and every hand-built batch write `StringArray::new_null` via one helper (D13); a NULL or absent hash at refresh → `NotRefreshable { MissingContentHash }` (recompute once). Path-valued image columns hash the path, not the file. Consequence, accepted: every fresh embedding table's Parquet bytes and artifact digest change (goldens/cookbook re-emit, C1); existing tables are untouched; embedded-vs-remote byte identity is unaffected.

**D5 — `publish_version` is the sole commit point.** One transaction: renew the version lease by CAS; `UPDATE result_table_versions SET status='ready', identity, live_rows, masked_rows, completed_at, lease_expires_at=NULL WHERE table_name AND version=N AND writer_id AND status='building'` (1 row); `UPDATE result_tables SET current_version=N, row_count=live_rows, input_anchors_json=$anchors WHERE table_name AND status='ready' AND current_version=P AND <tenant arm>` (1 row); a miss on the FIRST (version-row) CAS rolls back with typed `CasFailed` (the building-row lease class); a miss on the SECOND (table-row) CAS rolls back with `ParentMoved` when `classify_ready_cas_miss` finds the row `ready` but `current_version` disagreeing with `P` (round 5, M9), or `CasFailed` in its non-ready fallback. `<tenant arm>` is the STRICT pair `tenant_id = $t OR (tenant_id IS NULL AND $t IS NULL)` (`result_repo.rs:331-339`) on the allocation UPDATE, the base CAS, the publish CAS and every `result_table_versions` write: a scoped tenant can read a GLOBAL table (read-side OR-NULL, `:1108-1111`) but cannot refresh/compact/expire it; gated at step 0 by an explicit strict-pair comparison on the READ (before the model load and the scans) yielding `TenantMismatch`, and classified after a zero-row CAS by a sibling `classify_ready_cas_miss` (owner-less, status arm `!= ready`) rather than the BUILDING-row `classify_cas_miss` (`Owner = Writer | ExpiredLease`, `:252-267`), because a row a concurrent recovery flipped to `building` must not read as `LeaseLost` to a refresher; `read_cas_target` (`:387-403`) is unscoped so `TenantMismatch` vs `RowGone` is decidable. Nothing is visible before the CAS: an unpublished delta segment row carries `version = N`, the legacy branch lists `WHERE version IS NULL`, the versioned branch reads only a READY manifest reached through `current_version`, and the DataFusion provider is swapped only after the transaction (D8). Retry after `ParentMoved` (re-read the table row, restart from the new parent) or `CasFailed` is the consumer's.

**D6 — Actuators, no control loop** (`crates/jammi-ai/src/pipeline/recompute.rs:31-34`): `refresh_embeddings(table, RefreshOptions) -> RefreshReport`, `compact_embeddings(table) -> RefreshReport`, `expire_versions(table, before) -> ExpiryReport`, internal `publish_version`. No name carries a governance stem (`ci/scripts/check_no_consumer_names.py:14-22, :78-80`): `bind_result_table` (pub(crate)), `allocate_result_table_version`, `publish_version`, `fail_building_version`, `list_live_building_versions`, `list_expired_building_versions`, `list_base_index_segments`, `insert_index_segment_for_version`, `purge_segments_for_version`, `reap_version_artifacts`. No background compactor, GC loop or scheduler. All three verbs are exposed on the remote surface (library never less capable than server; expiry is a mechanism, when to call it is the consumer's).

**D7 — Deletes default to tombstone; `DeletePolicy::Retain` is opt-in** and recorded in the delta descriptor (K7). A table keeping rows the source no longer has is not "D over S" (`materialization-contract.md:13-19`); rolling-window knowledge is the consumer's (`docs/guide/src/philosophy.md:54-56`).

**D8 — `bind_result_table(ctx, record)` is the one registration path** for ready tables: `current_version` None → today's `register_table` (`store/mod.rs:855`); Some(N) → `MaskedTableProvider` from version N's manifest, registered through `ResultTableSchemaProvider::add_result_table(name, provider, owner)` (`store/result_schema.rs:77-87`); manifest unresolvable → the placeholder provider (D14). Called by startup (`store/mod.rs:1579-1619`), `BuildingTable::finish` step 4 (`store/building.rs:274-276`, always the None arm for a fresh table) and `publish_version`. `read_vectors` keeps today's raw base-bytes read when `current_version` is NULL (`crates/jammi-db/src/session.rs:975-984`, byte- and order-identical) and reads `SELECT vector FROM "jammi.{t}" ORDER BY _row_id` through the masked provider when Some (documented key order). `read_keyed_vectors` is exempt (external URL, `:996-1000`).

**D9 (K1) — Replay of a versioned table = full `EmbeddingPipeline::run` over the current source into a NEW single-segment table** (`recompute.rs:216-235` arm shape; `run` always `create_table`, `pipeline/embedding.rs:122-134`): value-equivalent, identity distinct, new chain root. `producing_descriptor(table)` returns the CURRENT version's manifest descriptor (`Embedding` at the base, `EmbeddingDelta` after a refresh, `EmbeddingCompaction` after a compaction), so both new `replay_descriptor` arms are reachable and doc-parity's replay leg is not vacuous (`ci/scripts/check_doc_parity.py:127-136`). No `MANIFEST_VERSION` bump (`manifest.rs:73`): `.materialization.json`'s shape is unchanged; the new variants appear only in `.version.json`, which carries its own `version_format = 1` reject-newer guard.

**D10 — Deterministic total order at the refresh plan AND both base sites, with the null-key check below the sort.** Today `InferenceExec` declares one output partition (`crates/jammi-ai/src/operator/inference_exec.rs:141-148`) but forwards `execute(partition)` to its input (`:206`); the embed pipeline builds a multi-partition scan (`embedding.rs:147-151`; `target_partitions = engine.execution_threads`, `crates/jammi-db/src/session.rs:188-190`), wraps it directly (`:154-166`) and executes partition 0 only (`:185-187`); `infer` has the identical shape (`crates/jammi-ai/src/session.rs:951-970`). One plan shape at all three sites: `scan (n partitions) → CoalescePartitionsExec → KeyCheckExec (§3.11) → SortExec(keys, preserve_partitioning = false) → InferenceExec`. Sort keys, a TOTAL order: `(CastExpr(col(key_column) → Utf8) ASC NULLS LAST, col("_content_hash") ASC NULLS LAST)`, where `_content_hash` is the `jammi_content_hash(...)` projection every source query carries (§3.2; at the `infer` site it is an input-only column the runner ignores and the fixed output schema never carries). Rows tied on both keys have equal `_row_id` and equal content and are mutually substitutable (candle pads per batch, so a vector is f(text, batch composition, device); every non-vector column of tied rows is identical, so the byte stream is invariant under permuting ties); the pinned arrow sort is unstable (`arrow-ord-57.3.0/src/sort.rs:170-178` used at `:409, :461, :501, :971`) and the Coalesce interleave is nondeterministic, which is why a partial key is not enough. The physical `CastExpr` defaults to `safe: false` (`PEX: expressions/cast.rs:34-36, :82`), so a key that cannot render fails loudly, never nulls. DF facts: `CoalescePartitionsExec` outputs `UnknownPartitioning(1)` (`DF: coalesce_partitions.rs:79-97`); `SortExec` with `preserve_partitioning = false` outputs one partition (`DF: sorts/sort.rs:954-957, :1064-1073`) but sorts only the input partition it is asked to execute (`:1267`) and merely declares `Distribution::SinglePartition` (`:1203-1210`) — satisfied by the optimizer in a planned query, not in a hand-built plan, hence the explicit Coalesce. Memory: the global sort is blocking and cannot spill (no memory pool is wired: `jammi-db/src/session.rs:188-190` sets only `target_partitions` and `batch_size`); the pipeline already collects every output batch (`embedding.rs:189`), so peak memory roughly doubles rather than changing class. Consequence, accepted: base artifact bytes change for every fresh table (row order becomes key order) — the fifth column already regenerates every golden in this PR — and bytes become identical across `execution_threads`, the engine's stated same-box contract (`crates/jammi-bench/src/propagate.rs:10-17`; `report.rs:332-334`; `crates/jammi-ai/src/query/vector_agg_udaf.rs:20-30`).

**D11 — Uniqueness.** Today's initial embed tolerates duplicate source keys (bare `SELECT`, `session.rs:1016-1038`; the sink writes every ok row, `pipeline/result_sink.rs:54-64`; `SidecarIndex::add` overwrites `row_index`, `sidecar.rs:787-788`) and keeps doing so (duplicates keep plan order among themselves, made deterministic by D10). Refresh refuses: `NonUniqueKey { table, keys: Vec<(String, u64)> (<= 10), total }` after a COMPLETE scan, checked on BOTH the source scan and the parent's masked current-state scan (a parent with two physical rows under one `_row_id` → `NonUniqueKey{parent}`; recompute once). Refused before any NEW version is allocated for this delta; on a first refresh of an unversioned table, the base version published by step 1 is retained (downstream-invisible: `identity(base)` is the base artifact hex, D3). A null key on the same scan is refused first (`InvalidKey` is raised by the stream at end of input, before the classifier's post-scan uniqueness check).

**D12 — Realized counts, all-invalid delta.** `ResultSink::write_batch` returns the ok row ids it realized; `RefreshReport.dropped_rows = |(Added ∪ Changed) \ realized|`; the mask entry for a dropped Changed key is still written (a full re-embed drops that row too, `result_sink.rs:103-106` — value-equivalent). An all-invalid delta does NOT inherit the base refusal (`embedding.rs:223-229`): it is a legitimate mask-only publish (no fragment, no segment, mask entries written, `row_count` reduced). `live_rows` at publish = `COUNT(*)` over the masked provider of the not-yet-published manifest (exact, row space, masked by the projection contract of §3.5); `masked_rows = Σ fragment rows − live_rows`; fragment rows are counted via `count_parquet_rows` (`storage/reader.rs:28`; a whole-object read, only the new fragment per refresh); base: `live = row count, masked = 0`. Emptiness policy is backend-specific: candle marks an empty text a per-row error (`model/backend/candle.rs:1882-1885, :2018-2021`); the HTTP backend short-circuits an empty input LIST (`model/backend/http.rs:74-82`) and otherwise forwards texts verbatim, so per-row validity is the remote's. The fixture binds candle; docs state per-backend validity.

**D13 — Null-hash batch builder lives in jammi-db** beside `embedding_batch` (`store/mod.rs:2242`) as `pub fn store::schema::embedding_batch_with_null_hash(schema, source_id, model_id, rows, dimensions)`, re-exported by `jammi-test-utils` for test sites; `jammi-bench` and jammi-db library sites call the jammi-db one. All 19 construction sites (P48) and both doc schema tables are in scope.

**D14 — Reconcile, recovery, and the two failure classes of a version.** `referenced_result_keys` (`reconcile.rs:998-1041`) adds, per ready table, every READY version row's manifest/fragments/deletes and every LIVE-building version's deterministic `__v{N}*` URLs and `version = N` segments (`list_live_building_versions`, `lease_expired_clause` idiom `catalog/lease.rs:146-158`); expired-lease building versions are unreferenced and are reaped by the recovery arm (`recover_inner` `store/mod.rs:1093-1101` gains `list_expired_building_versions` → claim → fail CAS → `reap_version_artifacts`). Recovery never promotes a version (a delta is cheap; the promote-from-sidecar arm exists for whole tables, `store/mod.rs:1103-1135`). Two failure classes, split: (i) manifest-RESOLUTION failure — the current version row is `failed`, or its manifest is definitively absent on an `exists()` probe — is typed `VersionUnavailable { table, version }` propagated by BOTH `resolve_search_mode` and the SQL path; "only definitive absence fails the VERSION row" (`status='failed'`, `current_version` unchanged, `result_tables` row untouched) is a rule about `exists()` probes and never about a scan `?`, because a mid-scan NotFound synthesized by the classifier (D20) is indistinguishable from definitive absence by shape; an `exists()` ERROR propagates as a storage error. Startup registers a PLACEHOLDER provider for a versioned table whose current manifest cannot be resolved: registered with the row's owner via `add_result_table(name, provider, owner)` (`result_schema.rs:77-87`) so `visible()` (`:105-110`) still hides it from peers (no existence disclosure), schema = `embedding_table_schema(dimensions) + _content_hash` off the catalog row (so planning succeeds), `scan` returns `DataFusionError::External(Box::new(JammiError::VersionUnavailable{..}))`, which D20's classifier restores to the typed variant for every SQL caller; registering nothing would instead surface a stringly planner not-found (`result_schema.rs:137-140` returns `Ok(None)`), and registering the base provider would resurrect deleted rows. A versioned row with `dimensions = None` is a catalog invariant violation: startup logs `warn!` and `continue`s (the skip-on-error shape `store/mod.rs:1579-1619`). (ii) segment-BUNDLE load failure → today's exact fallback over the MASKED provider. `reconcile_ready_manifests` (`store/mod.rs:1491-1530`) keeps its table-level arm for `.materialization.json` only; `purge_segments`/`delete_objects_after_cas` (`:1790`, `:1861`) stay table-scoped and reachable only from the table-level building/failed arms (invariant I-A2). The remedy for `VersionUnavailable` is `recompute` (new table).

**D15 (K4) — Byte identity is asserted at the VERSION identity.** Determinant set of a version's bytes = f(row MULTISET, D10's total order, write-batch cadence, pinned writer props). Writer props are pinned (ZSTD, `max_row_group_size 65_536`, `storage/writer.rs:30-33`). Same operation, same host: identity, fragment digests, deletes digest and counts equal; `produced_by`/`produced_at` differ (`manifest.rs:892-895` shape). Delta-vs-full and compaction-vs-chain are different operations: value-equivalent, identity distinct.

**D19 — Definition drift.** `definition_of(Embedding descriptor rebuilt from the current version's parameters, env)` (`manifest.rs:940-945`) ≠ `result_tables.definition_hash` → `DefinitionDrift { table, recorded, current }` before any allocation; the consumer runs `recompute`. ### 3.2 `_content_hash` production

`jammi_db::store::content_hash::{content_hash_row, ContentHash}` (pure; `sha2`/`hex` already deps) plus an Arrow kernel over `&[ArrayRef]`; `jammi_ai::query::content_hash_udf` registers the variadic `ScalarUDF jammi_content_hash(...)`. `build_source_query` (`session.rs:1016-1038`, shared by embed, `infer` and refresh) gains `jammi_content_hash("c1", "c2", …) AS _content_hash` over the RAW columns — no SQL `CAST` (D4). `InferenceExecBuilder::passthrough(Vec<String>)` copies named input columns to the output (`inference/schema.rs:30-41` gains the fields; the runner copies the arrays per emitted sub-batch); the embed and refresh sites pass `["_content_hash"]`, `infer` passes nothing (its output schema is fixed, `schema.rs:12-21`). `filter_ok_and_extract_vectors` maps `_content_hash` to the fifth column (NULL when absent). The UDF's typed refusals (binary column for a text task; a column the runner cannot render) surface through D20's arm (a). Hash decode at every reader validates 64 lowercase hex chars (K2). Pre-DELTA tables (four columns) and null-hash tables → `NotRefreshable { MissingContentHash }`.

### 3.3 Refresh algorithm — `refresh_embeddings(table, RefreshOptions{deletes: DeletePolicy}) -> RefreshReport`

Lives in `crates/jammi-ai/src/pipeline/embedding_refresh.rs`, exposed on `InferenceSession` and `local_session::Session` beside `recompute` (`local_session.rs:556`).

0. **Gates.** Tenant-scoped `get_result_table` + the strict-pair read gate (D5); require `status = ready`, `kind = model`, embedding task, and — when `current_version` is Some — a `ready` version row, else `NotRefreshable { CurrentVersionUnavailable }`. Duplicate key → collected, `NonUniqueKey{source}` after the complete scan (<= 10 keys with exact counts). Classify each key: `Added` (not in current), `Changed` (hash differs), `Unchanged`; `Deleted = current \ seen` unless `Retain`.
5. **Empty delta** → `RefreshReport { outcome: NoChange }`; nothing written for the delta, no delta version allocated, anchors untouched; a base version published by step 1 is retained (§6.16).
6. **Allocate** version N: one write transaction `UPDATE result_tables SET next_version = next_version + 1 WHERE table_name = $t AND status = 'ready' AND <tenant arm>` (1 row, else `classify_ready_cas_miss`) → `SELECT next_version, current_version` in the same transaction (Postgres row lock serialises allocators; SQLite has one writer) → `N = next_version − 1`, assert `current_version = P`. The transaction issues NO read before the UPDATE (a read-then-write transaction on SQLite/WAL can fail `SQLITE_BUSY_SNAPSHOT`, which `busy_timeout` does not retry, `backend_sqlite.rs:231`; on PG the row lock serialises allocators under the default READ COMMITTED, which the catalog uses — REPEATABLE READ would abort the second allocator) → `INSERT result_table_versions (t, N, P, 'building', manifest_path, writer_id, lease, tenant, created_at)`. `BuildingVersion` heartbeats via `renew_version_lease` CAS on `(table, version, writer_id, status='building')` (`building.rs:399-432` shape); its Drop is a best-effort `building → failed` CAS on the VERSION row with no byte deletion (`building.rs:364-392` shape).
7. **Infer the delta.** `(Added ∪ Changed)` keys → `MemTable(_row_id Utf8)`; plan = source scan with hash projection (probe, right) `HashJoinExec(Inner, CollectLeft, build = MemTable, on CastExpr(key)=_row_id)` (probe-side partitioning, `DF: joins/hash_join/exec.rs:592-602`, `joins/utils.rs:1526-1535`) → `CoalescePartitionsExec` → `KeyCheckExec` (a no-op guard here: step 4 already refused nulls) → `SortExec(D10 keys)` → `InferenceExec.passthrough(["_content_hash"])`; a plan-builder unit asserts `partition_count() == 1` below the sort. `ResultSink::for_embeddings` writes `{table}__v{N}.parquet` and a `SidecarIndex` at the table's persisted precision (`building.storage_precision()` idiom, `store/mod.rs:1726-1735`); `write_batch` returns realized ok ids. 8. **Segment.** `BuildingVersion::append_segment(index)` → `insert_index_segment_for_version`: the same allocation loop (`store/mod.rs:1739-1756`), predicate = `result_tables.status='ready'` AND version row `(t, N)` `building` under this `writer_id` (tenant arm), stamps `version = N`, saves the bundle second.
9. **Deletes.** Start from the parent's map; for `K ∈ Changed ∪ Deleted`: `entry[K] = max(entry[K], N−1)`; write `{table}__v{N}.deletes.parquet` unless empty; assert no key of fragment N is masked.
10. **Manifest.** `fragments = parent.fragments ∪ {new}` (`{url, version, rows via count_parquet_rows, digest = ArtifactDigest::of_bytes}`), `segments = parent.segments ∪ {new}`, `deletes`, `delta.descriptor = ProducingDescriptor::EmbeddingDelta { model_id, task, source_id, columns, key_column, dimensions, parent_version: P, parent_identity, deletes: Tombstone | Retain }`, `delta.input_anchors = [unpinned_at_instant(source, now)]`, `live_rows`/`masked_rows` per D12 (over an unregistered masked provider of this manifest), `identity` per §3.6. Write `{table}__v{N}.version.json`.
11. **Publish** (D5); then `bind_result_table`, `ann_cache.invalidate_source(source_id)` (`session.rs:633`), evict `SegmentSetCache` entries for the table. On `CasFailed` OR `ParentMoved` (round 5, M9: a concurrent refresh/compaction already published past `P`) the writer calls `abort()`: `fail_building_version` CAS then `reap_version_artifacts(N)`.
12. **Report** `RefreshReport { table, version, parent_version, inferred_rows, added, changed, deleted, unchanged, dropped_rows, live_rows, masked_rows, outcome: Published | NoChange }`.

Failure modes: any error in 6–11 unwinds through `BuildingVersion` Drop (version row → failed, bytes left for reap); explicit `abort()` deletes only artifacts stamped N (`reap_version_artifacts`: `__v{N}.parquet`, `__v{N}.deletes.parquet`, `__v{N}.version.json`, `purge_segments_for_version(t, N)` = `index_segments WHERE version = N` + sidecar siblings) — never `{table}.parquet`, `.materialization.json`, or a `version IS NULL` segment. Expired lease → recovery (D14). `result_tables.status`/`writer_id` are never touched by refresh or compaction (I-A2).

### 3.4 Read path — ANN

`resolve_search_mode(table)` (`store/mod.rs:1666-1696`): `current_version` None → `list_base_index_segments` (`WHERE version IS NULL ORDER BY segment_id`) and today's path; Some(N) → `SegmentSetCache.get_or_load((table_name, Some(N)))` → `Arc<LoadedSegmentSet { index: SegmentedIndex, mask: Arc<DeletionMask>, dead_per_segment }>`: load version N's manifest (resolution failure → `VersionUnavailable`, D14(i)), load ONLY its listed segments by `(table_name, segment_id)` through `segment_cache` (`:1678-1681`), load the deletes file into `DeletionMask { HashMap<String, i64> }`, build `SegmentedIndex::new_masked(segments_with_versions, mask)`. Bundle load failure → `None` → exact fallback over the bound (masked) provider (D14(ii)). Legacy tables cache under `(table_name, None)` (a ready table's base segment set is frozen: `segment_repo.rs:111-115` requires `building`). Eviction on `publish_version`, `bind_result_table`, table delete. Cache soundness: a version's SEMANTIC content is immutable once ready (manifest written before publish; a losing concurrent base publisher's PUT may land after the winner's CAS differing only in `produced_by`/`produced_at`, which verify and identity exclude; number never reused).

`SegmentedIndex` masked search: at construction `dead_per_segment[s] = |{K : mask[K] >= s.version ∧ s.contains(K)}|` (`SidecarIndex::contains` = `row_index` lookup, O(1); O(|mask| × N_seg) once per load). Per query and segment: `w = over_fetch(m, N)`; if `dead[s] > 0`, `w = ceil(w / (1 − dead[s]/len(s)))` capped at `len(s)`; loop `hits = s.search(q, w)` → drop `K` where `mask[K] >= s.version` → stop when `>= m` live or `w >= len(s)`, else `w = min(2w, len(s))`. Empty mask → exactly one search at today's width, so the N=1 byte-identity test (`segment.rs:353-367`) is unchanged. Candidates carry `SegmentId` into `search_final`; rescore calls the OWNING segment's `get_exact` (fixing `:271-278`); the dedup pass stays as defence. Per-query cost: `N_seg` probes × widening rounds (one in the common case) + one candidate filter pass; memory O(|mask|) once per loaded set. Seam note beside `DEFAULT_SEGMENT_OVERFETCH_FACTOR` (`segment.rs:85`).

Accepted read semantics (documented): a publish between the table-row read and the cache lookup serves version v (a consistent older snapshot); an in-flight read holding a loaded set for a since-expired version completes from memory (rescore companion is an open fd, `sidecar.rs:284-287`, which survives unlink on POSIX; remote bundles are in the local cache, `index_cache.rs:131-143`); a read that must LOAD an expired version fails the load → `None` → exact fallback over the currently bound provider; a mid-scan object vanish surfaces as typed `Storage(StorageError::Io { source: object_store::Error::NotFound })` via D20, never a partial answer.

### 3.5 Read path — SQL / exact

`bind_result_table` builds `MaskedTableProvider { fragments: Vec<(ListingTable, version)>, mask, schema }`. `scan(projection, filters, limit)` contract: (1) the pushed-down projection is remapped to always include `_row_id`; (2) each fragment is scanned with `limit = None` (ListingTable consumes `limit` two ways — file-list truncation and `with_limit` on the scan — `LST: table.rs:402, :426-433, :493`, so a pushed fetch under the mask would return fewer than `LIMIT n` live rows); (3) `UnionExec` over the per-fragment scans (sum of partitions, `DF: union.rs:173-178`), each wrapped in `MaskExec(fragment_version)` (arrow filter on `_row_id`, skipped when no mask entry has horizon >= that version); (4) `ProjectionExec` back to the caller's columns. `supports_filters_pushdown` is not overridden (default keeps `FilterExec` above the mask). `MaskExec` MUST NOT override `supports_limit_pushdown()` (default `false`, `DF: execution_plan.rs:509-511`) nor `with_fetch()` (default `None`, `:515`), so the outer fetch survives above the mask (`OPT: push_down_limit.rs:94-108`; `POPT: limit_pushdown.rs:195-256`: a non-pushdown node gets a `LimitExec` above it); a unit assertion pins both. The base fragment's provider comes from `build_result_table_provider` (`store/mod.rs:2380-2409`); the union schema is pinned by passing the base fragment's inferred `SchemaRef` to every `ListingTableConfig::with_schema` (`LST: config.rs:125`); a divergent file → typed `JammiError::Schema`. ### 3.6 Identity (K7) and verification

`identity(base) = manifest.artifact.0` (D3). For every version N with parent P: `SHA-256("jammi.version.identity.v1" ‖ "\0parent\0" ‖ len‖parent_identity ‖ "\0definition\0" ‖ len‖definition_hash ‖ "\0delta\0" ‖ len‖canonical(delta.descriptor) ‖ "\0fragments\0" ‖ Σ len‖fragment.digest (manifest order) ‖ "\0deletes\0" ‖ len‖deletes.digest-or-"")`, length-prefixed u64 LE, domain-separated as `manifest.rs:1003-1011`. Counts, segments (the ANN index is never attested, `store/mod.rs:972`), `produced_by`/`produced_at` are outputs, not inputs. `result_digest_anchor`/`current_anchor` for a table with `current_version` Some(N) return version N's identity from the catalog row (`freshness.rs:441-449`, `store/mod.rs:920-931` gain the arm), so a refresh that changed content advances dependents to `Stale{InputAdvanced}` and one that did not leaves them `Fresh`. `verify_materialization` on a versioned table: base check unchanged, plus recompute every listed fragment digest and the deletes digest, recompute identity, compare to the manifest and the catalog row; `MatchVerdict::Mismatch` names the artifact.

### 3.9 Sharding seam (design only; no wire change)

Coordinator runs §3.3 steps 0–6 and 9–11; fan-out `ComputeSpec::Embedding { partition: KeyRange, into_version: VersionTarget { table, version: N, writer_token } }` × n (D17), each shard writes `{table}__v{N}_p{i}.parquet` (five columns, sorted) + one segment via `insert_index_segment_for_version` under the token (segment ids may interleave; zero-row shards write nothing) and reports `(url, digest, realized_rows, segment_id)`. The fan-in job (depends on all shards — GRAPH provides the edges) builds `fragments[]` from the shard reports in partition order — never from an object listing; a missing report fails typed — writes the deletes and manifest and runs `publish_version`. A failed shard fails the fan-in; the version lease expires; recovery reaps. Correct for n concurrent shards because visibility depends only on the version number allocated once before fan-out and the single CAS.

### 3.12 The classifier (D20)

```rust
impl From<DataFusionError> for JammiError {
    fn from(e: DataFusionError) -> Self {
        match unwrap_jammi(e) {                       // shape (a): owned passthrough
            Ok(inner) => inner,
            Err(e) => match not_found_path(&e) {      // shape (b): borrowed source() walk
                Some((path, original)) => JammiError::Storage(StorageError::Io {
                    path: path.clone(),
                    source: object_store::Error::NotFound { path, source: Box::from(original) },
                }),
                None => JammiError::DataFusion(e),
            },
        }
    }
}
```

`unwrap_jammi(e) -> Result<JammiError, DataFusionError>` destructures by value: `External(b)` → `b.downcast::<JammiError>()` (`Ok(j) => Ok(*j)`, `Err(b) => Err(External(b))`); `Context(msg, inner)` → recurse, rebuilding `Context(msg, Box::new(back))` on miss; `ArrowError(b, bt)` → if `*b` is `ExternalError(inner)` downcast `inner`, rebuilding on miss; `ParquetError(b)` → if `*b` is `External(inner)` likewise; every other variant → `Err(e)` unchanged. `not_found_path(&e) -> Option<(String, String)>` walks `let mut cur: &(dyn Error + 'static) = &e` via `source()` and returns the first `object_store::Error::NotFound { path, .. }` it can `downcast_ref` (the `path` and the original's `Display`). Unit test (C1, the fast RED): `Context("opt", External(Box<InvalidKey{..}>))` → `InvalidKey` (arm a); `ParquetError(Box(ParquetError::External(Box(object_store::Error::NotFound{path:"t__v1.parquet", ..}))))` → `Storage(Io{path == "t__v1.parquet", source: NotFound{..}})` (arm b); `Plan("x")` → `DataFusion(Plan("x"))` and `ArrowError(Box(ArrowError::SchemaError("x")), None)` → `DataFusion(..)` with `std::error::Error::source(&j).is_some()` (the `#[source]` attribute survived).
