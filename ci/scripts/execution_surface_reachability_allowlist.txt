# Execution-surface reachability allowlist (check_execution_surface_reachability.py)
#
# Format: one row per line, `<exact tuple text><TAB><reason>` (a literal TAB
# character, never ` | ` — several tuples below pipe their own output
# through `tee`, e.g. `... 2>&1 | tee "$L1"`, so a `|`-based delimiter would
# collide with the tuple's OWN text). `#`-prefixed and blank lines are
# ignored. A row's tuple text is re-verified against the CURRENT registry
# (ci/scripts/**) on every run — a row naming a tuple whose script was
# renamed/deleted, or whose exact command line changed, FAILS as rot; a row
# whose tuple has become reachable on the merge path FAILS as a dead waiver.
# Neither is ever silently skipped.
#
# Every reason below cites STABLE CONTENT (a quoted phrase, a script/job
# name, an invariant this repo's own comments already state), never a bare
# line number — a line number rots the moment ANY unrelated PR touches the
# cited file.
#
# HONEST RESIDUAL (see the gate's own module doc "Honest residual" section):
# every row below needs a real CUDA/CUTLASS toolchain to run meaningfully.
# `runpod_gpu_prove.sh` (the driver script several rows below reference) is
# invoked from exactly ONE workflow, `gpu-prove.yml`
# (`workflow_dispatch` / `pull_request: types: [labeled]` / an
# allow-listed nightly `schedule` — deliberately no `push:`/`workflow_call:`
# trigger and no workflow may `uses:` it, `check_gpu_prove_once.py`'s P1
# rule pins this by name; the cron itself is a reviewed
# `PAID_LANE_CRON_ALLOWLIST` entry, P8 — any OTHER paid pod lane picking up
# a `schedule:` trigger is a finding until a human adds it there, naming its
# own never-vacuous arm). Every CUDA release lane (`server-image.yml`,
# `release-binaries.yml`, `pypi-server-cuda.yml` — the last calls
# `_gpu-proof-required.yml` DIRECTLY; `_pypi-server.yml` carries no gate at
# all, only the build/package steps) instead consumes that commit's
# already-recorded verdict through `_gpu-proof-required.yml` — a hermetic
# API read, never a second invocation of this driver script.
# NOT merge-path: `gpu-prove.yml`'s own triggers are label/dispatch/
# an allow-listed schedule only, and it is never `push:`-triggered by a tag
# either (a dev dispatches it by hand before tagging). The residual
# survives via that trigger scoping alone, not via "only one caller" —
# promoting this workflow to a REQUIRED merge-path check is a GitHub
# branch-protection ruleset setting, not committed workflow YAML, so
# nothing in this checkout can verify it — `GPU_PROVE_PROMOTED_TO_REQUIRED`
# in the gate script stays `False` until a human flips it (with a comment
# recording how the promotion was verified). Until then every row below is
# the honest, written, non-silent choice: each
# tuple stays off the merge path BY NAME, not by omission.
