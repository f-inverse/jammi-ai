# Reviewed require-gate helpers for check_kernel_oracles.py's KO-7 rule
# (docs/maintainer/cuda-kernel-guide.md §3). A #[test] fn's runtime skip
# (`let Some(d) = <helper>() else { return; };` and its siblings — see
# check_kernel_oracles.py's own module doc) is GATED only if its skip
# window contains a call to a NAME listed here — never by scanning any
# fn's body for a shape that merely LOOKS like a gate (three straight
# rounds of audit found a new way to fake that shape: an unrelated
# `.expect(` inside the if-block, an uncalled closure's `panic!`, a
# conforming gate written as `match` instead of `if`).
#
# Each entry is verified at gate time to have the CANONICAL shape: a real
# RUNTIME env-read (std::env::var_os/var — option_env! is a COMPILE-TIME
# read and is never accepted) of a JAMMI_REQUIRE_* name — a literal, or a
# bare identifier resolved, same-file, to a `const NAME: &str = "...";`
# whose value carries that prefix — via `if` or `match` (an `if` condition
# may carry additional `&&`-joined conjuncts in ANY position — e.g. a
# require-gate FOLDED INTO its own accessor legitimately leads with the
# accessor's own not-already-satisfied check — but never a `||`, and never
# a literal `true`/`false` conjunct; a `match` arm must be unguarded), whose
# taken-when-set branch is EXACTLY ONE panic!/unreachable! statement — no
# .expect(, no closures, nothing else, however the condition is shaped.
# Verification is (file, fn)-SCOPED: an entry only reviews the fn named
# `fn_name` DEFINED IN `file` itself (never a same-named fn elsewhere), and
# fails if that file defines more than one fn with that name (ambiguous —
# this scanner does not track `mod` boundaries). A line that fails is a
# registry FAIL naming the file:line and why. An exact duplicate
# `<file>::<fn_name>` line fails too. Adding a line here is a reviewed PR
# diff, same discipline as a citation or a `no-producer:` opt-out — the
# registry may only grow by entries the shape-check accepts.
#
# `file` may carry a leading `shared:` prefix (`shared:<file>::<fn_name>`)
# to opt a helper into CROSS-FILE gating: any OTHER file's skip may be
# gated by a BARE call to the name (provided that calling file does not
# itself define a same-named local fn — an unregistered local decoy must
# never "borrow" the shared review) or by a CRATE-QUALIFIED call whose
# qualifier is exactly the declaring file's own crate name (accepted
# regardless of a local decoy, since the qualifier disambiguates). This is
# for a require-gate FOLDED INTO the ONE accessor it guards — every caller
# is gated for free, with no per-file wrapper to remember (the twelve-copy
# duplication this gate exists to prevent in the first place). Two files
# may never both register the same name `shared:` — ambiguous, a registry
# FAIL. A file that wants to call a helper it does not itself define, and
# that helper is NOT registered `shared:`, still registers its own thin
# local wrapper of the same canonical shape (gating stays file-scoped by
# default — `shared:` is an explicit, reviewed opt-in, never the default).
#
# An entry whose OWN body does not carry the canonical shape may still
# verify by DELEGATION, one hop: a bare, SAME-FILE call to another name
# that IS verified for that file (from an entry ABOVE it in this same
# registry). This is for a same-file convenience wrapper that FORWARDS to
# the real accessor (`let url = pg_url_for_tests()?;`) rather than reading
# the env a second, independent time — the wrapper is exactly as safe a
# skip-guard as the accessor it calls. One hop only; a wrapper of a
# wrapper does not chain.
# Known, deliberate, fail-CLOSED limitation (round-5 audit A2): gating
# looks for a literal, BARE call to the registered NAME — `let g =
# cuda_device; g();` (a same-file ALIAS binding, then calling the alias)
# does not gate, because the call site is textually `g(`, not
# `cuda_device(`. This fails closed (an aliased skip reads as UNGATED,
# never as a false green), so it is a documented limitation, not a bug to
# route around — the remedy is to call the registered name directly
# (`cuda_device()`), never assign it to a local first.
# Format: one `<file-relative-to-repo-root>::<fn_name>` per line.
